# 麦思哲（MaiSiZhe）智能Agent校园即时通讯系统 - 详细数据库设计文档

---

## 1. 数据库设计概述

### 1.1 设计原则
- **第三范式（3NF）**：数据规范化，减少冗余
- **高性能索引**：合理设计索引，优化查询性能
- **扩展性设计**：预留扩展字段，支持未来需求
- **安全性**：敏感信息加密存储

### 1.2 数据库选型
- **数据库类型**：MySQL 8.0+
- **存储引擎**：InnoDB（支持事务、行级锁）
- **字符集**：utf8mb4（支持emoji）

### 1.3 核心表结构总览

| 模块 | 表名 | 说明 |
|------|------|------|
| 用户模块 | user | 用户信息表 |
| 好友模块 | friend | 好友关系表 |
| 好友模块 | friend_request | 好友请求表 |
| 群组模块 | im_group | 群组信息表 |
| 群组模块 | group_member | 群成员表 |
| 群组模块 | group_creation_code | 班号-群映射表 |
| 消息模块 | im_message | 消息历史表（单表设计） |
| 消息模块 | private_read_cursor | 私聊已读游标 |
| 消息模块 | group_read_cursor | 群已读游标 |
| AI模块 | ai_session | AI会话表 |
| AI模块 | keyword_alert | 关键词提醒表 |
| 管理模块 | operation_log | 操作日志表 |

## 5. 消息模块表设计

### 5.1 消息历史表（im_message）

**核心设计**：采用单表设计 + 联合索引，拒绝按月分表陷阱

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PRIMARY KEY | 消息全局唯一ID（雪花算法） |
| chat_id | VARCHAR(64) | NOT NULL | 会话标识（私聊：p_uid1_uid2，群聊：g_gid） |
| seq_id | BIGINT | NOT NULL | 会话内连续递增序号（Redis INCR） |
| from_uid | BIGINT | NOT NULL | 发送者ID（AI为0） |
| content | TEXT | NOT NULL | 消息正文 |
| msg_type | TINYINT | NOT NULL DEFAULT 0 | 消息类型：0-文本，1-图片，2-文件，3-AI回答，4-AI摘要 |
| mentioned_user_ids | VARCHAR(500) | NULL | @提及用户ID列表（JSON数组） |
| file_url | VARCHAR(500) | NULL | 文件/图片URL |
| file_name | VARCHAR(200) | NULL | 文件名 |
| file_size | BIGINT | NULL | 文件大小 |
| is_revoked | TINYINT | NOT NULL DEFAULT 0 | 是否撤回：0-否，1-是 |
| replace_msg_id | BIGINT | NULL | 被替换的消息ID（AI占位替换用） |
| create_time | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |

**索引设计**：
| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| PRIMARY | id | 主键索引 | 全局唯一检索 |
| uk_chat_seq | chat_id, seq_id | 唯一索引 | **核心：保证会话内消息唯一性和查询速度** |
| idx_from_uid | from_uid | 普通索引 | 按发送者查询 |
| idx_create_time | create_time | 普通索引 | 按时间范围查询 |

**设计说明**：
- **chat_id设计**：私聊格式为 `p_${uid1}_${uid2}`（uid1 < uid2保证唯一性），群聊格式为 `g_${gid}`
- **seq_id设计**：通过Redis INCR生成，保证每个会话内消息绝对连续递增
- **消息类型**：支持文本、图片、文件、AI回答、AI摘要等类型

## 9. 缓存与数据库交互策略

### 9.1 缓存设计

| 缓存Key | 类型 | 说明 | TTL |
|---------|------|------|-----|
| online:user:{uid} | String | 用户在线状态 | 60秒 |
| chat:msg:{chat_id} | ZSet | 热消息缓存（最近100条） | 无（LRU淘汰） |
| seq:chat:{chat_id} | String | 会话消息序号 | 无 |
| client:msg:{client_msg_id} | String | 消息去重标记 | 5分钟 |
| user:info:{uid} | Hash | 用户信息缓存 | 30分钟 |

### 9.2 读写策略

**写入流程**：
1. 消息写入 MySQL（主库）
2. 更新 Redis ZSet 缓存
3. 更新 Redis Stream 消息总线

**读取流程**：
1. 查询热数据：优先读 Redis ZSet
2. 查询历史数据：读 MySQL
3. 用户信息：优先读 Redis Hash，未命中读 MySQL

### 9.3 一致性保障

- **最终一致性**：采用先写DB后写缓存策略
- **缓存失效**：数据更新时删除缓存，下次读取时重建
- **消息可靠性**：Redis Stream 保证消息不丢失
