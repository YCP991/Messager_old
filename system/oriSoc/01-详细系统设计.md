# 麦思哲（MaiSiZhe）智能Agent校园即时通讯系统 - 详细系统设计文档

---

## 1. 系统概述

### 1.1 系统名称
**麦思哲（MaiSiZhe）** —— 基于 Vue3 + Spring Boot 的智能 Agent 校园即时通讯系统

### 1.2 系统定位
面向校园场景的小型团队即时通讯平台，融合 AI Agent 能力，为班级、课程组、实验室、社团等组织提供即时通讯服务和智能协作辅助。

### 1.3 核心价值主张
- **轻量级私有化部署**：适合小型团队，易于部署和维护
- **AI协作能力**：集成AI助手，支持智能问答、群日报、关键词提醒
- **校园场景深度适配**：班级群、课程群自动组建，贴合真实校园业务
- **高可靠性**：消息不丢、不乱、不重，支持断线重连和消息漫游

## 3. 总体架构设计

### 3.1 架构风格
采用 **模块化单体架构（Modular Monolith）**，兼顾开发效率和未来扩展：
- 代码层面解耦，业务边界清晰
- 三个人可以并行开发
- 后续可平滑升级为微服务

### 3.3 核心数据流

#### 3.3.1 消息发送流程
```
客户端发送消息
      │
      ▼
WebSocket Handler 接收
      │
      ▼
消息去重 (Redis SETNX)
      │
      ▼
双轴定序 (Snowflake ID + Redis INCR)
      │
      ▼
异步持久化 (MySQL)
      │
      ▼
热缓存写入 (Redis ZSet)
      │
      ▼
消息总线广播 (Redis Stream)
      │
      ▼
多节点消费并推送
```

#### 3.3.2 断线重连流程
```
WebSocket 断开
      │
      ▼
记录最后收到的 seq_id
      │
      ▼
触发重连机制 (指数退避)
      │
      ▼
重连成功
      │
      ▼
HTTP 请求增量消息 (/message/sync?lastSeq=xxx)
      │
      ▼
优先查 Redis ZSet
      │   │
      │   └─► 未命中 → 查 MySQL
      ▼
客户端排序合并
      │
      ▼
无缝恢复消息
```

## 5. 关键技术设计

### 5.1 消息双轴定序设计

**设计原理**：采用双轴定序机制，保证消息的全局唯一性和会话内连续性

```java
// 双轴定序实现
public class MessageSequenceService {
    // 雪花ID - 全局唯一，用于检索
    private SnowflakeIdGenerator snowflakeGenerator;
    
    // Redis INCR - 会话内绝对连续，用于判断丢包
    public Long generateSeqId(String chatId) {
        String key = RedisKeyConstants.SEQ_ID_PREFIX + chatId;
        return redisUtil.incr(key);
    }
    
    public MessageId generateMessageId(String chatId) {
        return MessageId.builder()
            .globalId(snowflakeGenerator.nextId())
            .seqId(generateSeqId(chatId))
            .build();
    }
}
```

**优势**：
- **全局唯一**：Snowflake ID 保证全局唯一性
- **顺序性**：Redis INCR 保证会话内消息绝对连续递增
- **丢包检测**：客户端根据 seq_id 判断是否有消息丢失
- **去重**：客户端生成 clientMsgId，服务端去重

### 5.2 WebSocket 长连接设计

**连接管理**：
```java
public class UserSessionManager {
    // ConcurrentHashMap 维护用户与连接的映射
    private ConcurrentHashMap<Long, WebSocketSession> sessionMap;
    
    // 心跳检测，超时断开
    public void heartbeat(Long userId) {
        // 更新在线状态
        redisUtil.set(RedisKeyConstants.ONLINE_USER + userId, "online", 60);
    }
    
    // 推送消息到指定用户
    public void pushToUser(Long userId, Message message) {
        WebSocketSession session = sessionMap.get(userId);
        if (session != null && session.isOpen()) {
            session.sendMessage(new TextMessage(message.toJson()));
        }
    }
}
```

**消息分发**：
```java
public class MessageDispatcher {
    // 根据消息类型路由到不同处理器
    public void dispatch(WebSocketSession session, WSMessage message) {
        switch (message.getType()) {
            case PRIVATE_CHAT:
                privateMessageHandler.handle(session, message);
                break;
            case GROUP_CHAT:
                groupMessageHandler.handle(session, message);
                break;
            case AI_MESSAGE:
                aiMessageHandler.handle(session, message);
                break;
        }
    }
}
```

### 5.3 分布式消息路由

**Redis Stream 作为消息总线**：
```
节点A 发送消息 ──► Redis Stream ──► 节点A消费 ──► 推送本地用户
                                ──► 节点B消费 ──► 推送本地用户
                                ──► 节点C消费 ──► 推送本地用户
```

**优势**：
- **水平扩展**：支持多节点部署
- **消息可靠**：自带 ACK 机制
- **消费组**：支持多个消费者组
- **持久化**：消息持久化到磁盘

### 5.4 AI 异步削峰设计

**设计原理**：将 AI 请求异步化，避免阻塞 WebSocket I/O 线程

```java
// AI 任务队列配置
@Configuration
public class AiThreadPoolConfig {
    @Bean(name = "aiTaskExecutor")
    public Executor aiTaskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(8);
        executor.setQueueCapacity(500);
        executor.setThreadNamePrefix("ai-worker-");
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.DiscardOldestPolicy());
        executor.initialize();
        return executor;
    }
}

// AI 工作流程
public class AiWorkflowService {
    @Async("aiTaskExecutor")
    public void processAtAiMessage(AtAiTask task) {
        // 1. 立即返回占位消息
        messageService.sendPlaceholder(task.getChatId());
        
        // 2. 拉取上下文
        List<Message> context = messageCache.getRecentMessages(task.getChatId(), 5);
        
        // 3. 调用大模型
        String response = llmClient.call(task.getQuestion(), context);
        
        // 4. 发送结果
        messageService.sendAiResponse(task.getChatId(), response);
    }
}
```

## 6. 权限体系设计

### 6.1 三维复合权限模型

```
权限判定 = 全局角色 × 资源类型 × 群内身份
```

**全局角色**：
| 角色 | 标识 | 权限说明 |
|------|------|---------|
| 学生 | STUDENT | 可创建普通群，不可创建班级群/课程群 |
| 教师 | TEACHER | 可创建课程群，自动成为群主 |
| 管理员 | ADMIN | 跨群操作，全权限 |

**群类型**：
| 类型 | 标识 | 创建权限 |
|------|------|---------|
| 普通群 | NORMAL | 所有用户 |
| 班级群 | CLASS | 班长/辅导员 |
| 课程群 | COURSE | 教师 |

**群内身份**：
| 身份 | 标识 | 权限说明 |
|------|------|---------|
| 群主 | OWNER | 最高权限，可转让群主 |
| 管理员 | ADMIN | 可管理成员，发布公告 |
| 普通成员 | MEMBER | 仅发送消息 |

### 6.2 权限注解设计

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface GroupPermission {
    // 需要的群内身份
    MemberRoleEnum[] requiredRoles() default {MemberRoleEnum.MEMBER};
    // 允许操作的群类型
    GroupTypeEnum[] allowGroupTypes() default {};
}

// AOP 切面实现
@Aspect
@Component
public class GroupPermissionAspect {
    @Before("@annotation(groupPermission)")
    public void checkPermission(JoinPoint joinPoint, GroupPermission groupPermission) {
        // 1. 获取当前用户
        Long userId = UserContextHolder.getUserId();
        
        // 2. 解析目标群ID
        Long targetGroupId = extractGroupId(joinPoint);
        
        // 3. 查询群类型和用户群身份
        Group group = groupService.getById(targetGroupId);
        GroupMember member = groupMemberService.getMember(targetGroupId, userId);
        
        // 4. 权限校验
        validatePermission(group.getType(), member.getRole(), groupPermission);
    }
}
```

## 8. 关键设计决策总结

| 设计点 | 决策 | 理由 |
|--------|------|------|
| 架构风格 | 模块化单体 | 兼顾开发效率和扩展性，后续可平滑升级微服务 |
| 消息存储 | MySQL单表+联合索引 | 拒绝按月分表陷阱，校园规模下单表足够 |
| 消息定序 | 双轴定序(Snowflake+INCR) | 保证全局唯一和会话内连续 |
| 消息总线 | Redis Stream | 支持分布式多节点部署，自带ACK |
| AI调用 | 异步线程池+阻塞队列 | 防止LLM高延迟阻塞I/O线程 |
| 权限模型 | 三维复合权限 | 角色×资源×身份，细粒度控制 |
| AI建模 | Agent-as-User | AI作为特殊用户，完美融入现有体系 |
