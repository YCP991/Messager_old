## 🎯 项目概述

**麦思哲(MaiSiZhe)** 是一个面向校园场景的智能Agent即时通讯系统，支持班级、实验室、社团等群组的实时通信和AI辅助功能。

**技术栈**:
- 前端: Vue 3.4 + TypeScript + Pinia + Naive UI
- 后端: Spring Boot 3.2 + MyBatis-Plus + JWT + WebSocket
- 数据库: MySQL 8.0 + Redis 7.x
- AI: DeepSeek/Qwen API (异步集成)

## 🎯 核心技术实现

### 1. JWT无状态认证

**流程图**:
```
客户端                          服务端
  |                               |
  |-- POST /api/auth/login ------>|
  |                               |-- 验证用户名密码
  |                               |-- 生成JWT Token
  |<-- {token, userInfo} --------|
  |                               |
  |-- GET /api/xxx (Header: Bearer token) ->|
  |                               |-- JwtFilter验证Token
  |                               |-- 设置SecurityContext
  |<-- 返回数据 ------------------|
```

**关键代码**:
```java
// 生成Token
String token = jwtUtil.generateToken(userId);

// 验证Token
boolean isValid = jwtUtil.validateToken(token);
Long userId = jwtUtil.getUserIdFromToken(token);
```

### 2. WebSocket实时通信

**连接建立流程**:
```
客户端                          服务端
  |-- WebSocket ws://host/ws/{token} ->|
  |                               |-- 验证JWT Token
  |                               |-- 保存Session到UserSessionManager
  |<-- SYSTEM_NOTIFICATION ------|
  |                               |
  |-- HEARTBEAT (每30秒) ------->|
  |<-- pong ---------------------|
```

**关键代码**:
```java
@ServerEndpoint("/ws/{token}")
public class WebSocketHandler {
    @OnOpen
    public void onOpen(Session session, @PathParam("token") String token) {
        Long userId = jwtUtil.getUserIdFromToken(token);
        sessionManager.addSession(userId, session);
    }
    
    @OnMessage
    public void onMessage(String message, Session session) {
        // 解析并路由消息
    }
}
```

### 3. Redis高性能缓存

**应用场景**:

1. **消息序列号生成** (原子自增):
```java
Long seqId = redisUtil.incr("seq:chat:" + chatId);
```

2. **热消息缓存** (ZSet):
```java
// 缓存最近100条消息
redisUtil.zAdd("chat:msg:" + chatId, message, seqId);
Object[] recentMessages = redisUtil.zRange("chat:msg:" + chatId, 0, 99);
```

3. **客户端消息ID去重** (SETNX):
```java
String key = "client:msg:" + clientMsgId;
if (redisUtil.hasKey(key)) {
    return; // 重复消息
}
redisUtil.setEx(key, "1", 300); // 5分钟过期
```

## 📈 数据库设计亮点

### 核心表结构

**im_message** (消息表):
```sql
CREATE TABLE `im_message` (
  `id` bigint NOT NULL COMMENT '消息ID(雪花算法)',
  `chat_id` varchar(64) NOT NULL COMMENT '会话ID',
  `seq_id` bigint NOT NULL COMMENT '会话内序列号',
  `from_uid` bigint NOT NULL COMMENT '发送者ID',
  `content` text NOT NULL COMMENT '消息内容',
  `msg_type` tinyint NOT NULL DEFAULT 0 COMMENT '消息类型',
  `mentioned_users` json DEFAULT NULL COMMENT '@的用户列表',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_chat_seq` (`chat_id`, `seq_id`)
) ENGINE=InnoDB;
```

**设计亮点**:
- ✅ 拒绝按月分表，采用单表+联合索引
- ✅ chat_id区分私聊(`p_uid1_uid2`)和群聊(`g_gid`)
- ✅ JSON字段存储@用户列表
- ✅ (chat_id, seq_id)保证消息顺序性

## 💡 关键技术决策

### 1. 为什么拒绝按月分表？

**原始设计**: message_202606, message_202607...

**问题**:
- ❌ 跨月查询性能差(需要UNION多表)
- ❌ 运维复杂度高(每月自动建表)
- ❌ 历史消息统计困难

**最终方案**: 单表 + (chat_id, seq_id)联合索引
- ✅ InnoDB聚簇索引使相同chat_id物理存储紧凑
- ✅ 历史消息查询是高效的顺序扫描
- ✅ 校园规模下单表千万级完全够用

---

### 2. 为什么选择原生WebSocket而非STOMP？

**STOMP局限性**:
- ❌ 内存Broker无法支持多节点部署
- ❌ 消息丢失风险高
- ❌ 自定义协议扩展困难

**原生WebSocket优势**:
- ✅ 配合Redis Stream实现集群广播
- ✅ 消息可靠性保障
- ✅ 灵活的自定义消息格式

---

### 3. 如何处理AI高并发？

**问题**: LLM响应慢(3-10秒)，同步调用会阻塞线程池

**解决方案**: 异步削峰工作流
1. 立即返回占位消息("AI正在思考中...")
2. 任务入队到BlockingQueue
3. 独立AI Worker线程池异步消费
4. 通过标准消息通道推送结果

```java
@Bean(name = "aiTaskExecutor")
public Executor aiTaskExecutor() {
    ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
    executor.setCorePoolSize(4);
    executor.setMaxPoolSize(8);
    executor.setQueueCapacity(500);
    return executor;
}
```
