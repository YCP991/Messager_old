## 二、详细分析

### 2.1 user 表

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY,           -- 雪花ID
    username VARCHAR(50) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    student_no VARCHAR(50) UNIQUE,
    real_name VARCHAR(50) NOT NULL,
    avatar VARCHAR(255) DEFAULT '/default-avatar.png',
    email VARCHAR(100),
    phone VARCHAR(20),
    class_no VARCHAR(50),
    department VARCHAR(100),
    role INT DEFAULT 0,              -- 0-学生,1-教师,2-管理员
    status INT DEFAULT 1,            -- 0-禁用,1-正常
    last_login_time DATETIME,
    last_login_ip VARCHAR(50),
    create_time DATETIME,
    update_time DATETIME
);
```

#### 优点 ✅
- 使用雪花ID保证分布式唯一性
- 学号唯一约束避免重复注册
- 角色和状态字段支持权限管理
- 头像字段有默认值

#### 问题 ⚠️
1. **缺少逻辑删除字段**
   - 影响：用户注销后无法恢复，数据无法"软删除"
   - 建议：添加 `deleted` 字段并添加 `@TableLogic` 注解

```sql
ALTER TABLE user ADD COLUMN deleted INT DEFAULT 0;
```

---

### 2.2 friend 表

```sql
CREATE TABLE friend (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    friend_id BIGINT NOT NULL,
    remark VARCHAR(100),
    is_pinned INT DEFAULT 0,
    sort_order DOUBLE,
    create_time DATETIME,
    update_time DATETIME,
    deleted INT DEFAULT 0,
    UNIQUE KEY uk_user_friend (user_id, friend_id, deleted)
);
```

#### 优点 ✅
- 逻辑删除支持
- 唯一约束防止重复好友
- 置顶和排序字段支持好友管理
- 备注字段灵活

#### 设计分析 🔍
**双向存储策略**：A和B是好友时，存储两条记录
- (A, B) - A视角的好友B
- (B, A) - B视角的好友A

**优点**：
- 查询好友列表简单（直接查 `WHERE user_id = X`）
- 支持各自设置不同的备注名

**缺点**：
- 数据冗余（每对好友存储两次）
- 添加/删除好友需要操作两条记录

#### 问题 🟡
1. **好友请求处理时只添加一条记录**
   - 当前逻辑：好友请求通过后，只添加一条好友记录
   - 建议：添加好友时应该添加两条记录（双向好友）

### 2.3 friend_request 表

```sql
CREATE TABLE friend_request (
    id BIGINT PRIMARY KEY,
    from_user_id BIGINT NOT NULL,
    to_user_id BIGINT NOT NULL,
    status INT DEFAULT 0,           -- 0-待处理,1-已同意,2-已拒绝,3-已过期
    remark VARCHAR(255),
    create_time DATETIME,
    update_time DATETIME,
    deleted INT DEFAULT 0
);
```

#### 优点 ✅
- 状态机设计清晰（待处理→已同意/已拒绝/已过期）
- 备注字段支持附加消息
- 逻辑删除支持

#### 问题 🟡
1. **缺少请求过期时间字段**
   - 当前：过期由代码逻辑判断
   - 建议：添加 `expires_time` 字段

```sql
ALTER TABLE friend_request ADD COLUMN expires_time DATETIME;
```

### 2.4 im_group 表

```sql
CREATE TABLE im_group (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    avatar VARCHAR(255) DEFAULT '/group-default.png',
    announcement TEXT,
    type INT DEFAULT 0,            -- 0-普通群,1-班级群,2-课程群
    owner_id BIGINT NOT NULL,
    class_no VARCHAR(50),
    course_id BIGINT,
    max_members INT DEFAULT 0,
    member_count INT DEFAULT 0,
    is_disbanded INT DEFAULT 0,
    disband_time DATETIME,
    create_time DATETIME,
    update_time DATETIME
);
```

#### 优点 ✅
- 群类型支持多种场景（普通群、班级群、课程群）
- 群主ID关联用户表
- 班级号和课程ID支持教学场景
- 成员数量统计字段

#### 问题 ⚠️
1. **缺少逻辑删除字段**
   - 影响：群解散后物理数据仍在，无法恢复
   - 建议：添加 `deleted` 字段

```sql
ALTER TABLE im_group ADD COLUMN deleted INT DEFAULT 0;
```

2. **群名称缺少唯一约束**
   - 建议：移除群名称唯一性限制（不同用户可创建同名群）

### 2.5 group_member 表

```sql
CREATE TABLE group_member (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    group_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    role INT DEFAULT 0,             -- 0-普通成员,1-管理员,2-群主
    group_nickname VARCHAR(50),
    is_pinned INT DEFAULT 0,
    sort_order DOUBLE,
    mute_until DATETIME,
    join_time DATETIME,
    quit_time DATETIME
);
```

#### 优点 ✅
- 角色字段支持权限管理
- 群昵称支持个性化
- 禁言字段支持群管理
- 退群时间字段设计合理（软退出）

#### 问题 ⚠️
1. **缺少逻辑删除字段**
   - 影响：历史成员记录无法区分是否在群
   - 建议：添加 `deleted` 字段

```sql
ALTER TABLE group_member ADD COLUMN deleted INT DEFAULT 0;
```

2. **缺少唯一约束**
   - 当前：一个用户可以多次加入同一群
   - 建议：添加 `UNIQUE KEY uk_group_user (group_id, user_id)`

### 2.6 im_message 表

```sql
CREATE TABLE im_message (
    id BIGINT PRIMARY KEY,
    chat_id VARCHAR(100) NOT NULL,
    seq_id BIGINT NOT NULL,
    from_uid BIGINT NOT NULL,
    to_uid BIGINT,
    group_id BIGINT,

    create_time DATETIME,
    update_time DATETIME

```

#### 优点 ✅
- 消息类型支持多种媒体
- @用户列表JSON存储灵活
- 序列号保证消息顺序
- 扩展字段支持功能扩展
- 撤回机制完善

#### 问题 🟡
1. **缺少逻辑删除字段**
   - 影响：敏感消息无法彻底删除
   - 建议：添加 `deleted` 字段

```sql
ALTER TABLE im_message ADD COLUMN deleted INT DEFAULT 0;
```

2. **消息未读状态未设计**
   - 影响：无法知道用户已读哪些消息
   - 建议：添加 `message_read` 记录表

## 四、设计改进建议

### 4.1 高优先级（影响功能）

#### 建议1: 统一添加逻辑删除字段

为 user、im_group、group_member、im_message 表添加逻辑删除：

```sql
-- user 表
ALTER TABLE user ADD COLUMN deleted INT DEFAULT 0 COMMENT '0-未删除,1-已删除';
ALTER TABLE user ADD INDEX idx_deleted (deleted);

-- im_group 表
ALTER TABLE im_group ADD COLUMN deleted INT DEFAULT 0 COMMENT '0-未删除,1-已删除';
ALTER TABLE im_group ADD INDEX idx_deleted (deleted);

-- group_member 表
ALTER TABLE group_member ADD COLUMN deleted INT DEFAULT 0 COMMENT '0-未删除,1-已删除';
ALTER TABLE group_member ADD INDEX idx_deleted (deleted);

-- im_message 表
ALTER TABLE im_message ADD COLUMN deleted INT DEFAULT 0 COMMENT '0-未删除,1-已删除';
ALTER TABLE im_message ADD INDEX idx_deleted (deleted);
```

**理由**：
- 用户注销、群解散、消息删除都需要可恢复能力
- 符合数据合规要求（GDPR等）
- 审计追溯需要

#### 建议2: 群组成员唯一约束

```sql
ALTER TABLE group_member ADD UNIQUE KEY uk_group_user (group_id, user_id);
```

**理由**：防止同一用户重复加入同一群

---

### 4.2 中优先级（优化功能）

#### 建议3: 添加消息已读表

```sql
CREATE TABLE message_read (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    message_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    read_time DATETIME NOT NULL,
    INDEX idx_message_user (message_id, user_id),
    INDEX idx_user_read (user_id, read_time)
) COMMENT '消息已读记录';
```

**理由**：
- 实现消息已读/未读状态
- 支持群聊的"谁看了这条消息"功能

#### 建议4: 添加好友请求过期时间

```sql
ALTER TABLE friend_request ADD COLUMN expires_time DATETIME;
```

**理由**：
- 简化过期判断逻辑
- 支持不同过期时间策略

### 4.3 低优先级（架构优化）

#### 建议5: 消息分表策略

当前问题：
- 单表消息量随时间无限增长
- 影响查询性能

建议方案：
- 按 chat_id 哈希分表
- 或按月份分表
- 或使用 ClickHouse 等时序数据库

## 五、SQL语句优化建议

### 5.1 好友列表查询优化

**当前查询**：
```sql
SELECT * FROM friend WHERE user_id = ? AND deleted = 0;
```

**优化建议**：添加复合索引
```sql
CREATE INDEX idx_user_deleted ON friend(user_id, deleted);
```

### 5.2 群成员查询优化

**当前查询**：
```sql
SELECT * FROM group_member WHERE group_id = ? AND quit_time IS NULL;
```

**优化建议**：添加索引
```sql
CREATE INDEX idx_group_quit ON group_member(group_id, quit_time);
```

### 5.3 消息历史查询优化

**当前查询**：
```sql
SELECT * FROM im_message WHERE chat_id = ? ORDER BY seq_id DESC LIMIT 50;
```

**优化建议**：添加索引
```sql
CREATE INDEX idx_chat_seq ON im_message(chat_id, seq_id DESC);
```
