### 2.2 前后端接口不匹配问题

#### 问题1: 消息发送接口缺少fromUid参数

**后端接口定义**:
```java
@PostMapping("/private")
public Result<MessageVO> sendPrivateMessage(
        @RequestParam Long fromUid,  // 需要URL参数
        @Valid @RequestBody SendMessageDTO dto)
```

**前端调用**:
```typescript
export function sendPrivateMessage(data: SendMessageDTO): Promise<MessageVO> {
  return request.post('/message/private', data);  // 未传递fromUid
}
```

**影响**: 发送消息会失败，因为后端无法获取发送者ID

---

#### 问题2: 消息撤回接口缺少userId参数

**后端接口定义**:
```java
@PostMapping("/recall")
public Result<Void> recallMessage(
        @RequestParam Long messageId,
        @RequestParam Long userId)  // 需要操作用户ID
```

**前端调用**:
```typescript
export function recallMessage(messageId: number): Promise<void> {
  return request.post('/message/recall', null, { params: { messageId } });
}  // 未传递userId
```

**影响**: 撤回消息会失败，权限校验无法通过

---

#### 问题3: 私聊历史接口缺少userId参数

**后端接口定义**:
```java
@GetMapping("/private/history")
public Result<List<MessageVO>> getPrivateHistory(
        @RequestParam Long userId,    // 当前用户ID
        @RequestParam Long peerId,    // 对方用户ID
        @RequestParam(defaultValue = "50") Integer limit)
```

**前端调用**:
```typescript
export function getPrivateHistory(peerId: number, limit: number = 50): Promise<MessageVO[]> {
  return request.get('/message/private/history', { params: { peerId, limit } });
}  // 未传递userId
```

**影响**: 获取私聊历史会失败

## 四、业务逻辑审查

### 4.1 发现的逻辑缺陷

#### 问题5: 群聊撤回通知广播范围错误

**问题位置**: `MessageServiceImpl.java:354`

```java
if (message.getGroupId() != null) {
    // 群聊撤回通知
    webSocketHandler.broadcastMessage(wsMessage);  // 广播给所有人
}
```

**问题**: 使用 `broadcastMessage` 会将撤回通知发送给所有在线用户，而不是仅发送给群组成员

**正确做法**: 应该遍历群组成员列表，逐个发送撤回通知

---

### 4.2 已修复问题

#### 问题6: FriendMapper缺少SQL注解（已修复）

**原问题**: `selectFriendCount`、`selectFriendIdsByUserId`、`selectByUserAndFriend` 方法缺少 `@Select` 注解

**修复**: 在 `FriendMapper.java` 中添加了对应的 SQL 注解

## 五、代码质量审查

### 5.1 代码重复问题

#### 问题7: getCurrentUserId 方法重复

**位置**: 
- `FriendController.java:262-268`
- `GroupController.java:260-266`

**问题**: 两个Controller中都定义了相同的 `getCurrentUserId()` 私有方法，存在代码重复

**优化建议**: 抽取为公共工具方法或基类

---

### 5.2 异常处理问题

#### 问题8: 业务异常处理不一致

**问题**: 部分接口返回 `Result.error(400, "xxx")`，部分直接抛出 `BusinessException`

**示例**:
```java
// FriendController
if (friend == null) {
    return Result.error(404, "好友不存在");  // 返回错误Result
}

// GroupController  
if (group == null) {
    throw new BusinessException("群组不存在");  // 抛出异常
}
```

**优化建议**: 统一使用异常处理方式，由全局异常处理器统一处理
